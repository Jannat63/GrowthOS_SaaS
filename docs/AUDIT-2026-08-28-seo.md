# Audit — SEO (`/seo`)

**Date:** 2026-08-28 · **Branch:** `shihab-restructure`

Seventh in the series, and the largest surface so far — five tabs behind one route. All 11 findings
below are fixed.

## Framing

Five tools sharing a header: rank tracker, topic clusters, organic traffic, a schema-markup
generator and an internal-link optimizer. Two of them report over a time window; three have no time
dimension at all — and the page header made a single time claim on behalf of all five.

The headline finding is the worst measurement bug found in this series: **the live organic-traffic
figures were six times the window their labels claimed.**

## A. Wrong or misleading

| # | Finding | Fix |
|---|---------|-----|
| S-01 | **"Clicks (30d)" summed 180 days.** Both queries in `getOrganicTraffic` ran with no date filter whatsoever — `WHERE workspace_id = {ws}` and nothing else — while `SEED_DAYS` is 180. The offline fallback builds exactly 30 days, so the same four tiles read one figure offline and **six times** that figure live, with identical labels. Connecting a backend multiplied every number on the tab by six for no visible reason. | Both queries windowed to `TRAFFIC_DAYS = 30`, anchored to the newest day with data via `getDataBounds`/`resolveWindow` (the seed ends at a fixed date, so a calendar window would match nothing once real time passed it). The response now carries `period`, and the tab prints the measured dates instead of a hard-coded "(30d)" — so the label cannot drift from the number again. |
| S-02 | **The header claimed "over the last 30 days" for all five tabs.** Clusters, schema markup and internal links have no time dimension; the rank tracker reports a 7-day change. And on seeded data the newest row is six weeks behind today, so the claim was wrong about the period as well as the scope. | The blanket claim is gone. Each tab that has a window prints its own measured dates. |
| S-03 | **The cluster tiles described a different page from the one beneath them.** `summary.clusters` counts every cluster including one-keyword ones (7 on the sample data) while the body deliberately separates those and calls them "Ungrouped" — so the tile said 7 topics over a page showing 1. `summary.keywords` is the *total* tracked count (8), labelled "Keywords grouped", when only 2 keywords are in a topic. | Tiles counted from what the page actually renders: Topics found (1), Keywords in a topic (2), Largest topic (2), Not grouped (6) — which also adds up to the 8 tracked keywords. |
| S-04 | **"Connect Google Search Console… to replace the sample data" rendered unconditionally**, including for a workspace that had already connected it. Search Console is the one integration wired end to end, so this told exactly the users who had done the work that their live data was sample data. | Gated on an active `google_search_console` connection. |

## B. Structure and behaviour

| # | Finding | Fix |
|---|---------|-----|
| S-05 | **Five tabs, one address.** `defaultValue` with no `value`/`onValueChange`: a link could only ever point at the rank tracker, a refresh discarded which tab you were on, and Back left the page rather than returning to the previous tab. | The open tab lives in `?tab=`, with `replace` so switching doesn't stack history between real navigations. Wrapped in the `Suspense` boundary `useSearchParams` requires — without it the build fails prerendering this route, which is how it was caught. |
| S-06 | **Ember on 16 non-actions.** Every keyword ranking 4–10 rendered its position in the `default` badge — the action colour, and the token `BrandingProvider` overwrites per tenant. A rank is a fact, not a button. | `outline` for page-one positions; `success` stays for top-3, `muted` for the rest. |
| S-07 | **The organic-clicks chart was coloured `--primary`** via `text-primary` on its card, while the rank sparklines on the same page use semantic success/destructive. Two encodings on one page — and a white-label tenant's chart hue changed with their brand colour, which CLAUDE.md explicitly warns against relying on. | `--channel-seo`, the colour this channel already carries everywhere else. |
| S-08 | `InternalLinkOptimizer` keyed rows on `targetPage` alone; two suggestions pointing at the same page from different sources collide. | Keyed on the source→target pair. |
| S-09 | Page URLs truncated at 320px with no way to read the rest. | `title` attribute carries the full URL. |

## Deliberate non-changes

- **`clusterKeywords` and its summary shape.** The engine is correct and tested; the finding was
  that the tiles mislabelled its output. `summary` is left intact for other consumers.
- **The internal-link optimizer stays read-only.** No dismiss, no "done", no export. That is a
  feature gap rather than a defect, and building a second recommendation lifecycle alongside the
  one in `recommendations` is a decision, not a fix.
- **The 30-day figure itself.** `TRAFFIC_DAYS` matches what the tab always claimed; the bug was that
  nothing enforced it. Making the window user-selectable is a separate change.
