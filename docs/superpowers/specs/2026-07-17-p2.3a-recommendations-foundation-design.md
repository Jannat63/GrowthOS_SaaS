# P2.3a — Recommendations Foundation — Design Spec

**Date:** 2026-07-17
**Milestone/Phase:** M2 · P2.3a (foundation half of P2.3)
**Status:** Approved design — ready for implementation plan
**Depends on:** P2.1 (db/api patterns), P2.2 (workspace profiles)

## Goal

Make recommendations a **real, backend-owned, persisted** entity, produced by the **one canonical
engine** — retiring the frontend mock-compute path. This is the contract deferred from P2.2. It sets
the pattern P2.4–P2.6 reuse. The paid-to-organic *feature* (search-terms scoring, content briefs,
Content Pipeline UI, act/dismiss/snooze) is **P2.3b**.

## Locked decisions

1. **Shared `@growthos/logic` package (single source of truth).** Extract the tested `lib/logic`
   engines **+ the seed fixtures they score** out of `apps/web` into a shared package imported by both
   `apps/web` and `apps/api`. No Python port; scoring is TS.
2. **Scoring runs synchronously in the API.** Seeded scoring is fast, deterministic, and non-external
   — it does not need the worker/queue (that's for M3's real external pulls).
3. **Generate-if-empty, then persist.** The first `GET /recommendations` for a workspace computes recs
   from the engine over fixtures and persists them; subsequent reads return the persisted rows. This
   is what makes act/dismiss/snooze (P2.3b) possible — you can't mutate a computed-on-read rec.
4. **`compositeScore` is a TS helper**, not a Postgres generated column (DB-portable; shared by API +
   web fallback so both agree).

## Scope (P2.3a only)

In scope:
- `@growthos/logic` package: engines + shared fixtures; `apps/web` re-pointed to it.
- `recommendations` table (Drizzle). *(`content_briefs` → P2.3b.)*
- Recommendation generator (API, TS): cross-channel engine over fixtures → mapped `recommendations`
  rows, persisted idempotently.
- `GET /workspaces/:id/recommendations` — generate-if-empty, return persisted rows.
- Unified `Recommendation` type in `@growthos/types`; `useRecommendations` + `RecommendationQueue`
  moved onto it and onto live persisted data (mock fallback = same engine over same fixtures).

Out of scope (→ P2.3b):
- Search-terms scoring endpoint, `content_briefs`, Content Pipeline page, `PATCH /recommendations/:id`
  (act/dismiss/snooze).

## The shared package

`packages/logic` (`@growthos/logic`):
- Moves `apps/web/lib/logic/*` (the 6 pure engines + their tests) verbatim.
- Moves the seed fixtures the engines consume (`apps/web/lib/mock-data/*`) under
  `@growthos/logic/fixtures` (or a sibling export) so both apps score identical data.
- Adds `compositeScore(impact, effort, urgency)` helper + a `toRecommendation(...)` mapper (below).
- `apps/web` imports updated: `@/lib/logic/*` → `@growthos/logic`, `@/lib/mock-data/*` →
  `@growthos/logic/fixtures`. Consumed via `transpilePackages` (like `@growthos/ui`).

Verification that the move is behavior-preserving: the moved engine tests pass unchanged, and
`pnpm --filter @growthos/web build` still compiles.

## Data model — `recommendations` (Drizzle)

Mirrors the blueprint (composite computed in app, not a generated column):

| column | type | notes |
|--------|------|-------|
| id | uuid pk | |
| workspaceId | text notNull | app-layer key |
| type | text notNull | e.g. `cross_channel` (paid_to_organic etc. in P2.3b) |
| sourceChannel | text notNull | seo \| google_ads \| meta_ads \| unified |
| targetChannel | text notNull | |
| title | text notNull | |
| body | text notNull | |
| actionLabel | text | |
| impactScore | integer notNull | 1–100 |
| effortScore | integer notNull | 1–100 |
| urgencyScore | integer notNull | 1–100 |
| compositeScore | integer notNull | app-computed: impact*0.5 + urgency*0.35 + (100-effort)*0.15 |
| status | text notNull default 'pending' | pending \| acted \| dismissed \| snoozed |
| rawData | jsonb | source signal |
| createdAt | timestamptz default now() | |

Index on `(workspaceId, status)`. No unique key — but generation is idempotent via a per-workspace
"already generated?" check (if any rows exist for the workspace, skip generation).

## Shared `Recommendation` type (`@growthos/types`)

Evolve the existing stub to the persisted shape:
```ts
export type RecommendationStatus = 'pending' | 'acted' | 'dismissed' | 'snoozed';
export interface Recommendation {
  id: string; workspaceId: string; type: string;
  sourceChannel: string; targetChannel: string;
  title: string; body: string; actionLabel: string | null;
  impactScore: number; effortScore: number; urgencyScore: number; compositeScore: number;
  status: RecommendationStatus;
}
```

## Mapping cross-channel engine → Recommendation

`generateCrossChannelRecommendations` yields `{ id, bridge, title, message, impact }`. The
`toRecommendation` mapper (in `@growthos/logic`) fills the richer shape deterministically:
- `bridge` → `sourceChannel`/`targetChannel` (e.g. `SEO→GoogleAds` → `seo`/`google_ads`).
- `impact` `High|Medium|Low` → `impactScore` `90|60|30`; `effortScore`/`urgencyScore` seeded defaults
  per bridge; `compositeScore` via the helper.
- `message` → `body`; `type` = `cross_channel`; `status` = `pending`.
This mapper is used by **both** the API generator and the web mock fallback → live and fallback agree.

## API

- `GET /workspaces/:id/recommendations` (min role `viewer`, `requireWorkspaceMember`):
  1. If no rows for the workspace, generate via `toRecommendation(generateCrossChannelRecommendations(
     scoreKeywords(fixtures.keywords), analyzeSearchTerms(fixtures.searchTerms),
     detectFatigueAll(fixtures.creatives)))` and insert.
  2. Return `{ data: Recommendation[], total }` ordered by `compositeScore` desc.

## Frontend unification

- `useRecommendations(workspaceId)` now fetches `GET /workspaces/:id/recommendations` (typed
  `Recommendation[]`); `liveOrMock` fallback runs the **same** `@growthos/logic` engine+mapper over the
  **same** fixtures — so the shape and content match live.
- `RecommendationQueue` re-typed to `Recommendation`: render `title`, `body`, a
  `sourceChannel→targetChannel` badge, and `compositeScore`/`impactScore`. Keep `DataSourceBadge`.

## Testing

- **`@growthos/logic`:** the moved engine tests pass unchanged; new tests for `compositeScore` +
  `toRecommendation` (bridge→channels, impact→score, composite ordering).
- **API (vitest):** `GET /recommendations` generates-if-empty then returns persisted rows; a second
  call does not duplicate (idempotent); ordered by composite desc.
- **Web:** `pnpm --filter @growthos/web build` compiles; `useRecommendations` returns the unified shape.
- **E2E (data layer):** call the generator for a test workspace → rows persisted → second call no-ops.
